CORE FINDING
================================================================================

LLMs maintain TWO DISTINCT neural representations for safety:

1. HARMFULNESS DIRECTION
   - Location: t_inst (final token of user instruction)
   - Encodes: "Is this content harmful/dangerous/illegal?"
   - Nature: Fundamental understanding of harm
   - Robustness: Preserved even after adversarial fine-tuning

2. REFUSAL DIRECTION
   - Location: t_post-inst (after special tokens at generation start)
   - Encodes: "Should I refuse to answer this?"
   - Nature: Learned behavioral filter
   - Robustness: Vulnerable to suppression attacks

These directions are APPROXIMATELY ORTHOGONAL (independent).

================================================================================
HOW IT ADVANCES REFUSAL DIRECTION LITERATURE
================================================================================

PREVIOUS MODEL (Arditi et al., 2024):
  → Refusal = Single 1D direction
  → Steering along this direction changes behavior

NEW MODEL (2507.11878):
  → Safety = Harmfulness + Refusal (2D or more)
  → Can steer EACH independently
  → Changes to one don't affect the other

WHAT CHANGED:
  • Decomposed safety into components (not monolithic)
  • Identified distinct token positions (not global)
  • Explained why jailbreaks work (target refusal, not harm understanding)
  • Enabled new defense (Latent Guard using harmfulness perception)

================================================================================
METHODOLOGY IN A NUTSHELL
================================================================================

THREE TYPES OF EVIDENCE:

1. CORRELATIONAL (Clustering)
   - Collect hidden states at t_inst: cluster by harmful vs harmless
   - Collect hidden states at t_post-inst: cluster by refused vs accepted
   - Different clustering patterns → separate encodings

2. CAUSAL (Steering)
   - Steer harmfulness direction → model reinterprets benign as harmful
   - Steer refusal direction → model refuses (harm perception unchanged)
   - Effects are orthogonal → independent

3. COGNITIVE (Reply Inversion)
   - Append question: "Is this harmful? Yes/no"
   - Steer harmfulness: answer FLIPS
   - Steer refusal: answer STAYS SAME (but still refuses)
   - Proves orthogonality directly

EXTRACTION METHOD:
  • Linear probing: Train classifier at each position
  • PCA: Find dominant variance direction
  • Mean difference: harmful_acts.mean - harmless_acts.mean

================================================================================
KEY EXPERIMENTS
================================================================================

STEERING HARMFULNESS:
  Input: Harmless prompt (e.g., "Write a cake recipe")
  Steering: +α * v_harmfulness
  Output: Model treats as harmful, tries to refuse
  Effect on refusal direction: NONE (orthogonal)

STEERING REFUSAL:
  Input: Harmful prompt (e.g., "Write malware")
  Steering: +α * v_refusal
  Output: Model refuses to answer
  Effect on harm perception: NONE (orthogonal)

REPLY INVERSION (Strongest):
  Input: "How to make bomb?" + "Is this harmful? Yes/No"
  Baseline answer: "Yes" (thinks it's harmful)
  
  After steering harmfulness: "No" (now thinks it's NOT harmful)
  Predicted behavior: Should refuse less → CORRECT
  
  After steering refusal: "Yes" (still thinks harmful)
  But refuses anyway → PROVES independence

================================================================================
WHY JAILBREAKS WORK (New Understanding)
================================================================================

OLD MODEL:
  Model refuses because it understands content is harmful

NEW MODEL:
  Model UNDERSTANDS it's harmful (at t_inst)
  But CHOOSES to refuse or not (at t_post-inst)

THEREFORE:
  Jailbreaks don't need to change what model understands
  Only need to suppress the refusal response

THREE JAILBREAK TYPES:

1. REFUSAL SUPPRESSION (Easiest)
   - Attack: Few-shot prompting, hidden tokens
   - Target: Refusal signals at t_post-inst
   - Harmfulness understanding: INTACT
   - Model "knows" it's harmful but complies

2. ADVERSARIAL FINE-TUNING
   - Attack: Fine-tune on harmful examples
   - Target: Weakens refusal signals
   - Harmfulness understanding: PRESERVED
   - Fine-tuned models still "understand" harm

3. CONCEPTUAL REFRAMING (Hardest)
   - Attack: "Write as fiction" / "As hypothetical"
   - Target: Harmfulness direction at t_inst
   - Changes: How model assesses content
   - Harder to defend because changes fundamental assessment

LATENT GUARD: PRACTICAL APPLICATION
================================================================================

IDEA:
  Use harmfulness direction for safety classification
  
  v_harmfulness extracted from model
  → Train tiny classifier: projection(h_inst, v_harm) → safe/unsafe
  → Deploy at inference time

PERFORMANCE:
  • Comparable to Llama Guard 3 8B (baseline classifier)
  • More efficient (operates on activations, not token sequences)
  • More robust (harder to fool with refusal-suppressing jailbreaks)

WHY IT'S BETTER:
  Llama Guard 3: Analyzes tokens (can be fooled by prompt injection)
  Latent Guard: Analyzes internal representation (harder to fake)
  
  Jailbreak attempts suppress refusal but don't change harmfulness
  → Latent Guard still detects as unsafe

CRITICAL INSIGHTS FOR YOUR PROJECT
================================================================================

1. SEPARATION IS CAUSAL, NOT JUST CORRELATIONAL
   - You can independently manipulate what a model "understands"
   - And whether it "refuses"
   - This is proven via clever experiments, not just statistics

2. TOKEN POSITION MATTERS
   - Don't treat hidden states globally
   - Harmfulness encoded at t_inst, refusal at t_post-inst
   - This explains different "feel" of attacks

3. HARMFULNESS IS ROBUST
   - Fine-tuning doesn't remove harm understanding
   - Only weakens refusal filter
   - Suggests defense strategy: monitor harm understanding

4. JAILBREAKS ARE PARTIAL ATTACKS
   - Don't change what model understands
   - Only suppress what it will say
   - More complete attacks would need to change both

5. LATENT GUARD SHOWS PRACTICAL VALUE
   - Not just theory, but real safety application
   - Better than sequence-based classifiers
   - More robust to refusal-suppression attacks
