## One-Paragraph Summary

This paper investigates using Sparse Autoencoders (SAEs) to steer model refusal by amplifying specific features that mediate safety behavior. While SAE steering successfully improves robustness against both single-turn and multi-turn jailbreaks (e.g., 45.45% ASR on Crescendo vs. 87.63% baseline), the authors discover a significant hidden cost: **systematic degradation of unrelated capabilities**. MMLU accuracy drops from 68.80% to 35.98%, GSM8K from 82.50% to 35.56%, revealing that refusal-mediating features are deeply entangled with general language abilities. This finding directly challenges the assumption that safety mechanisms can be isolated and manipulated without harming broader model performance, raising critical questions for the Refusal-Cones RDO approach.

## Key Findings

### Finding 1: Safety-Capability Tradeoff Is Real

**SAE steering results:**

| Metric | Baseline | SAE Steering | Change |
|--------|----------|-------------|--------|
| **Refusal on Crescendo** | 55.92% ASR | 32.58% ASR | +23.34pp ✓ |
| **MMLU (70K questions)** | 68.80% | 35.98% | -32.82pp ✗ |
| **GSM8K (math)** | 82.50% | 35.56% | -46.94pp ✗ |
| **TruthfulQA** | 65.00% | 53.82% | -11.18pp ✗ |

**Interpretation:** Can achieve safety improvements, but at crippling capability cost.

### Finding 2: Not Due to Over-Refusal

**Important:** Capability degradation is NOT because the model refuses legitimate requests.

- Model doesn't refuse math problems
- Doesn't refuse factual knowledge questions
- Performance breaks even on "safe" benign domains (chemistry, history)
- Suggests: feature amplification creates out-of-distribution activations

### Finding 3: Problem Is General, Not Specific to Refusal

**Ablation test:** Amplified philosophy feature (Feature 216, unrelated to refusal) shows comparable degradation

**Implication:** Issue is "a limitation of feature steering writ large," not specific to safety/refusal

**For RDO:** If RDO uses different mechanism (projection vs. amplification), might avoid this

### Finding 4: Jailbreak Robustness Is Real

**Good news:** Safety improvements are genuine and robust against adversarial escalation

- Single-turn: +37.69pp improvement in refusal rate
- Multi-turn Crescendo attacks: -42.18pp on Molotov category
- Generalizes across diverse harm categories
- Resists iterative attack escalation

**For RDO:** Need to demonstrate similar adversarial robustness

### Foundation: Arditi et al. (2024)

SAE paper builds on Arditi et al.'s finding: "Refusal in language models is mediated by a single direction"

| Paper | Finding | Implication |

| **Arditi (2406.11717)** | Single refusal direction exists | Refusal is geometrically simple |
| **SAE (2411.11296)** | Single refusal feature is powerful | Can improve safety by amplifying |
| **Refusal-Cones** | Single direction is cone-shaped | Can ablate via projection |

**The contrast:** While all agree refusal is localized, they disagree on:
- **Arditi:** Direction (dense, geometric)
- **SAE:** Feature (sparse, saliency-based)
- **RDO:** Cone (multi-dimensional, structured)

### SAE's Critique of Pure Direction-Based Approaches

"Vector steering derives directions from contrasting prompt pairs... but SAE steering identifies features through sparse activation patterns, offering finer granularity."

**Translation:** SAE authors believe single-direction models (like Arditi's) may be missing the real structure.

**Implication for RDO:** If SAE is right, discovering multi-dimensional cone (RDO's goal) is more accurate than assuming single direction.

## Technical Insight: Why SAE Steering Fails

### The Mechanism

```
SAE decoder is learned linear map: h_reconstructed = decoder @ f

If Feature 22373 is correlated with:
  ✓ Refusal keywords
  ✓ Safety training signal
  ✗ Also with: formal language, technical tone, information content

Amplifying feature 22373 amplifies ALL correlated patterns
  → Over-activates formal language → capability loss
  → Out-of-distribution activations → model confusion
  → No learned mechanism to compensate
```

### Why RDO Might Avoid This

```
Projection doesn't use a learned decoder:
  h_projected = h - (h·v)v

Removes ONLY the component along v, preserves everything orthogonal
  → Exact mathematical operation, no learned artifacts
  → In-distribution activations (model trained on these)
  → Multi-objective training penalizes capability loss
```

**Key difference:** SAE amplifies a proxy; RDO directly ablates the target direction.

## Implications for Safety-Capability Entanglement

### What SAE Paper Establishes

1. **Refusal features are not isolated:** Amplifying them breaks unrelated capabilities
2. **Problem is not over-refusal:** Degradation occurs on safe inputs
3. **Mechanism unknown:** Authors explicitly state "reasons remain unclear"
4. **Fundamental research gap:** How to separate safety from capability

### What This Means for RDO

**Optimistic interpretation:**
- RDO's geometric/projection approach might be cleaner than SAE's feature amplification
- Multi-objective training (λ_retain) should prevent similar entanglement
- Prediction: RDO shows <10pp capability degradation vs. SAE's 46pp

**Pessimistic interpretation:**
- If refusal IS entangled with capabilities (SAE suggests it is), RDO will also suffer
- Projection is cleaner than amplification, but still removing a direction with mixed semantics
- Prediction: RDO shows 15-25pp degradation

**Middle ground:**
- Tradeoff space exists (different λ_retain settings offer different safety-capability points)
- RDO can optimize this frontier better than SAE could
- Prediction: RDO achieves pareto frontier where safety > baseline, capability ≈ baseline
