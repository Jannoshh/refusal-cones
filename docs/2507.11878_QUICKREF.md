# Quick Reference: LLMs Encode Harmfulness and Refusal Separately (2507.11878)

## One-Sentence Summary
LLMs maintain separate neural encodings for **harmfulness perception** and **refusal behavior**, with independent geometric directions and different token position localization.

---

## Key Finding

```
Safety ≠ Single direction (Arditi et al.)
Safety = Harmfulness Direction + Refusal Direction (orthogonal)
```

### Evidence Type: Trichotomy

| Evidence | Finding |
|----------|---------|
| **Correlational** | Clustering at `t_inst` separates by content; clustering at `t_post-inst` separates by behavior |
| **Causal (Steering)** | Steering harmfulness changes perception; steering refusal changes behavior; effects are orthogonal |
| **Cognitive (Reply Inversion)** | When steered on harmfulness, model flips "is this harmful?" answer. When steered on refusal alone, it refuses but answer unchanged. |

---

## Token Positions

| Concept | Position | What Encodes | How to Access |
|---------|----------|--------------|---------------|
| Harmfulness | `t_inst` (last token of instruction) | "Is this harmful?" | Hidden state at instruction end |
| Refusal | `t_post-inst` (after special tokens) | "Should I refuse?" | Hidden state at generation start |

**Insight:** Model decides "harmful or not" at the instruction, then separately decides "refuse or not" at generation.

## Methodology Essentials

### 3-Phase Approach

```python
# Phase 1: Direction Discovery (Clustering Analysis)
harmful_states = model.get_hidden_states(harmful_prompts, position="t_inst")
harmless_states = model.get_hidden_states(harmless_prompts, position="t_inst")

                                         filter=lambda x: x.refused)
accepted_states = model.get_hidden_states(all_prompts, position="t_post-inst",
                                          filter=lambda x: not x.refused)
refusal_direction = pca_direction(refused_states, accepted_states)

# Phase 2: Causal Verification (Steering)

output = model.forward_with_intervention(h_steered)
```

## Core Experiments

### Experiment 1: Steering Harmfulness
**Setup:** Apply harmfulness direction vector
**Result:** Model reinterprets benign requests as harmful
**Does it trigger refusal?** No—refusal unchanged (orthogonal)

### Experiment 2: Steering Refusal
**Setup:** Apply refusal direction vector
**Result:** Model refuses to answer
**Does it change harm judgment?** No—perception unchanged (orthogonal)

### Experiment 3: Reply Inversion (Strongest Evidence)
```
Append: "Is the user's request harmful? Answer yes or no."

Manipulation 1: Steer HARMFULNESS direction
  - Model's "yes/no" answer FLIPS
  - Behavioral prediction: Should refuse less now (thinks harmless)
  - Actual behavior: MATCHES prediction

Manipulation 2: Steer REFUSAL direction ONLY
  - Model's "yes/no" answer UNCHANGED (still thinks harmful)
  - But model REFUSES anyway
  - Proves: Can refuse without changing harm judgment
```

## Why Jailbreaks Work (New Understanding)

### Previous Model
```
Model understands "this is harmful"
  → Refuses

Jailbreak changes: Refuses (somehow)
```

### New Model
```
Model understands "this is harmful"    [at t_inst]
  AND
Model is programmed to refuse          [at t_post-inst]

Jailbreak targets: Refusal signals (leave understanding intact)
Result: Model knows it's harmful but responds anyway
```

### Three Jailbreak Categories

1. **Refusal Suppression** (easiest)
   - Target: Refusal direction at `t_post-inst`
   - Effect: Model complies despite understanding harm
   - Examples: Few-shot prompting, hidden tokens

2. **Fine-tuning on Harmful Data**
   - Target: Weakens refusal signals
   - Harmfulness understanding: STAYS INTACT
   - Why fine-tuned models still "understand" harm but comply

3. **Conceptual Reframing** (hardest)
   - Target: Harmfulness direction at `t_inst`
   - Effect: Model recontextualizes as non-harmful
   - Examples: "Write as fiction," "As a hypothetical"
   - Harder to defend because actually changes assessment

## Latent Guard: Practical Application

### Idea
Use the harmfulness direction as a safety classifier:
- Extract harmfulness direction from model
- Train tiny linear classifier: harmfulness activations → safe/unsafe
- Deploy on `t_inst` activations (where harm is encoded)

### Performance
- Matches or beats Llama Guard 3 8B
- More efficient (operates on activations, not token sequences)
- More robust (harder to fool via refusal-suppressing jailbreaks)

### Why It's Better Than Llama Guard
```
Llama Guard 3: Analyzes token sequence (can be fooled by prompt injection)
Latent Guard:  Analyzes model's internal harm assessment (harder to fake)
```
